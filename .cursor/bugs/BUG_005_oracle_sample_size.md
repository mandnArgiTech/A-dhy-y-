# [CLOSED] BUG-005 — Oracle validation samples are too small to be meaningful

**Severity:** MEDIUM — gives false confidence in coverage  
**Phase blocked:** 6.1, 6.2 acceptance criteria honesty  
**Files affected:** `tools/run_vyakarana_oracle.py`, `tools/run_scl_oracle.py`  
**Depends on:** BUG-001, BUG-002 (must be fixed first)

---

## Symptom

After all the validation infrastructure was set up, the actual sample size is:

| Oracle | What's tested | What was promised |
|--------|---------------|-------------------|
| `tinanta_oracle_results.tsv` | **9 rows, 1 root (BU)** | "≥99% match on 254,736 forms" |
| `subanta_oracle_results.tsv` | **7 rows, 6 distinct stems** | "≥99% on a-stem masculines" |
| `shabdaprakriya` step matching | **0 rows — script doesn't exist** | "≥70% sūtra attribution match" |

`tools/run_vyakarana_oracle.py` has:

```python
SUPPORTED_VALIDATE_ROOTS = {"BU"}
MAX_VALIDATE_ROWS = 1000
```

The MAX_VALIDATE_ROWS is high enough — but the SUPPORTED set caps it at 1 root × 9 forms = 9 rows.

## Required fix

Sample sizes should match the README's claims:

| Oracle | Required sample | Rationale |
|--------|----------------|-----------|
| Tiṅanta | ≥ 50 dhātus × LAT × P × 9 = 450 forms | Cover gaṇas 1, 4, 6, 10 + ubhayapada |
| Subanta | ≥ 50 stems × 24 forms = 1,200 forms | Cover P/S/N + ā-stem + i/u-stem + consonant stem |
| Prakriyā trace | ≥ 100 derivations × ~3 steps = 300 step rows | Subanta only initially (oracle has 4,863 rows) |

Stratified random sampling from the source TSVs:
- **Tiṅanta**: 12 from gaṇa 1, 8 from gaṇa 2, 8 from gaṇa 4, 8 from gaṇa 6, 8 from gaṇa 10, 6 ubhayapada
- **Subanta**: 20 a-stem masc, 10 ā-stem fem, 8 i-stem, 6 u-stem, 6 consonant-stem
- **Prakriyā trace**: 100 forms drawn proportional to vibhakti distribution

The sampler should use a deterministic seed (e.g. `random.seed(42)`) so the sample is stable across runs but representative.
